# Spatial selection and canvas transformations

In canvas overview, choose **Select** to drag a selection rectangle on empty canvas. It selects intersecting windows/cards and the actual geometry of annotations, excluding empty corners around arrows and ellipses. Hold **Ctrl** while drawing to add to the selection. **Ctrl-click** toggles individual items in both Select and Windows modes. Clicking an already selected item keeps the group; dragging it moves the group. Middle-drag pans; Windows mode also retains left-drag panning on empty space.

Click a **project name** to select its tile, explicitly assigned saved windows, and annotations/windows whose centers lie inside the tile. Explicit members remain part of that project even when they are outside its boundary. Overlapping neighbouring tiles are independent. A selection rectangle must enclose a whole project tile to select the tile and expand its contents; a small marquee inside a large tile selects just the local objects. This uses existing saved window membership plus current spatial placement, and does not silently rewrite saved project memberships.

**Nearby → Radius in canvas units → Select around camera** selects a snapshot around the center of the primary display's camera viewport. Windows and annotations intersecting the circle are included. A project tile must fit entirely within the circle before its group is included, avoiding accidental selection of an enormous enclosing project. The world-space radius stays constant as you zoom; pan and zoom afterward do not change the selection. The circle marks the location used for that snapshot. The radius is saved as `SelectionRadius` in `config.ini` (default 1200, range 1–100000).

Dragging shows outline ghosts without changing saved positions. Release commits the validated group once; **Escape**, capture loss, a desktop switch, or leaving overview cancels an unfinished drag. Single selected annotation handles still resize; double-click a selected note to edit its text. **Ctrl+Z/Y** in Select mode and the toolbar Undo/Redo replay a group move as one step, including its annotations, project tiles, saved windows and cards. Group moves, annotation edits and project layout commands share chronological Ctrl+Z/Y and toolbar Undo/Redo; a new edit clears both redo branches. A stale or removed member prevents partial history replay. Moving a group does not open an application; minimized/maximized applications retain their state and receive updated restore positions. Persistence/native projection failures retain the logical layout and report the workspace warning.

Open **AI Compose** with a selection to start with those context entries checked. The list can be edited before sending. Only checked annotation text/kinds/bounds and checked window titles/project names/bounds are sent; application contents, screenshots, files, executable paths, launch targets, other objects and the local obstacle list are excluded. The limit is 20 checked items and 32,000 text characters. Project selection is already expanded in the canvas, so its effective contents appear as separate reviewable entries.

Actions include organizing themes, showing dependencies, generating a roadmap or summary, and improving layout while keeping wording. Existing shared annotation IDs let the model propose a semantic order/graph; local code computes positions. Reused notes/shapes retain their exact wording, kind, dimensions and style. Layout-only proposals must include every checked note/shape, and cannot add notes, rewrite text or add arrows. Selected arrows follow rearranged endpoints. Windows and project tiles are reference context for the assistant; this version moves them only through direct user gestures. AI proposals remain translucent previews until Apply, with one annotation undo step. Changed annotations, desktop changes and changed shared place metadata prevent stale proposals from applying.

The reusable selection model and gesture state live in `Modules/CanvasView/CanvasSelection.cs`. The overview host provides scoped identities and capture, the workspace service validates and persists saved-ID placement batches, and the existing annotation history coordinates both halves of a mixed move. Selection is session-only and clears on a virtual-desktop switch.

## Windows smoke checks

- Marquee across notes, shapes and window cards; Ctrl-add and Ctrl-remove; move the result, cancel once with Escape and once by losing capture, then commit and Undo/Redo.
- Place a window and note inside a project tile, assign an additional saved member outside it, and select the name. All should select and move together once. A small marquee inside the tile must not select the full project.
- Check Nearby at two zoom levels and after panning; the world radius and selection snapshot should stay fixed. Restart to check the saved radius.
- Switch virtual desktops during a marquee and a group drag. No geometry should commit to either desktop.
- Open AI Compose from each selection method. Review/uncheck context, generate a roadmap and a layout-only proposal, then Apply/Undo. Verify unchanged wording and stale-context rejection.
- Repeat selection, drawing, pan, double-click activation, and single-note handle resizing on a negative-origin monitor at mixed DPI. Check toolbar and context-list readability on the target display.
